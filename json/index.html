Online JSON/YAML/XML/CSV/JSONL Formatter and JSONPath Query

Make JSON easier to read, check its syntax, convert between JSON, YAML, XML, CSV, TSV, JSONL and Markdown tables, or query the current data with JSONPath. The formatter uses your browser’s parsers and serializers; processing happens locally.

How to Format and Validate JSON

  1. Paste a JSON object or array into the input area, or load the sample.
  2. Choose an indentation size and select Format. Use the tree view to inspect nested values.
  3. Select Validate to check syntax, or Compress to produce compact JSON.
  4. Copy the output after checking the result.

Import YAML as JSON

YAML mappings become JSON objects, sequences become arrays, and anchors, aliases and merge keys are resolved. Multiple YAML documents separated by --- are converted into a JSON array and reported as a warning.

Binary values, complex non-scalar keys, circular aliases and unsupported tags are rejected instead of being silently converted.

  1. Paste or import YAML and keep the input format on Auto-detect, or choose YAML explicitly.
  2. The page validates the YAML and converts it to a JSON value.
  3. Inspect the result in the JSON tree, text or table view, then copy or download it as JSON.
YAML:
user:
  name: Alice
  tags:
    - admin
    - editor
  active: true

JSON:
{
  "user": {
    "name": "Alice",
    "tags": ["admin", "editor"],
    "active": true
  }
}

Import XML as JSON

Attributes use the @ prefix, text content uses #text when attributes or child elements are present, and repeated item elements become arrays. The root element is kept by default.

XML has no native number or boolean types, so text stays as strings unless type inference is enabled. Mixed content may lose its original order, namespace prefixes are preserved by default, and DOCTYPE declarations are rejected.

  1. Paste or import XML and keep the input format on Auto-detect, or choose XML explicitly.
  2. Adjust the XML input options if needed: keep the root element, unwrap item arrays, or choose how empty elements are represented.
  3. Inspect the JSON result in the tree, text or table view, then copy or download it.
XML:
<user id="42">
  <name>Alice</name>
  <tags>
    <item>admin</item>
    <item>editor</item>
  </tags>
  <note/>
</user>

JSON:
{
  "user": {
    "@id": "42",
    "name": "Alice",
    "tags": ["admin", "editor"],
    "note": null
  }
}

Import or export CSV/TSV

CSV is a flat format. Nested objects and arrays are written as compact JSON by default, or can be flattened with dot-separated column names. Type, null, empty-string and structure differences may be lossy.

CSV output guards cells that start with spreadsheet formula characters. Duplicate or empty headers and rows with different lengths are reported as warnings.

Use Field mapping to choose, rename and reorder columns, flatten nested paths, join arrays, and set basic type transforms. Mapping applies only to the current conversion and does not modify the input.

  1. Paste or import CSV/TSV and keep Auto-detect, or choose the format explicitly.
  2. Choose whether the first row is a header, the delimiter, type inference and empty-cell handling.
  3. For JSON to CSV, choose how nested objects and arrays are written, then copy or download the table.
JSON:
[{"name":"Alice","age":30},{"name":"Bob","age":25}]

CSV:
name,age
Alice,30
Bob,25

Import or export JSONL

JSONL stores one complete JSON value per line. Blank lines are ignored, and a JSON string containing a newline must escape it as \n so the record stays on one line.

Strict mode reports the first invalid line with its line number. Skip mode keeps valid records and lists skipped lines in the input warnings.

  1. Paste JSONL and keep Auto-detect, or choose JSONL as the input format.
  2. Choose whether invalid lines should stop parsing or be skipped with warnings.
  3. For JSON to JSONL, arrays are expanded to one compact JSON value per line by default.
JSON:
[{"id":1},{"id":2}]

JSONL:
{"id":1}
{"id":2}

Export JSON as a Markdown Table

Nested objects and arrays are written as compact JSON inside cells. Pipes are escaped and line breaks become <br> so the table stays valid.

A top-level array of primitives becomes a single value column, and an array of arrays becomes numbered columns.

  1. Enter or import valid JSON and set the output format to Markdown.
  2. Arrays of objects become one table row per object; a plain object becomes a key/value table.
  3. Copy or download the generated .md table.
JSON:
[{"name":"Alice","role":"admin"},{"name":"Bob","role":"editor"}]

Markdown:
| name | role |
| --- | --- |
| Alice | admin |
| Bob | editor |

Query JSON with JSONPath

The query supports root $, child properties, quoted keys, array indexes, wildcards, slices, recursive descent with .., and filters with @, comparisons and &&/||.

Queries run against the current parsed input, so YAML, XML, CSV, TSV or JSONL input is queried as its JSON value. Query results are limited to keep the page responsive.

  1. Open the JSONPath Query tab and enter an expression such as $.store.book[?(@.price < 10)].title.
  2. Run the query to see matching paths, values, tree, table and text views.
  3. Copy the result or export it as JSON or CSV.
Query:
$.store.book[?(@.price < 10)].title

Result:
[
  "Sayings of the Century",
  "Moby Dick"
]

Generate TypeScript or JSON Schema

TypeScript output creates named interfaces for nested objects. Arrays of objects merge their fields, and fields missing from some items become optional.

JSON Schema output uses Draft 2020-12, infers integer/number/string/boolean/null types, writes required fields from the merged structure, and can allow or disallow additional properties.

  1. Open the Generate tab with valid parsed input.
  2. Choose TypeScript or JSON Schema, set the root name, and decide whether fields should be optional.
  3. Copy the generated code or download it as .ts or .json.
JSON:
{"user":{"name":"Alice","tags":["admin"]}}

TypeScript:
export interface User {
  name: string
  tags: string[]
}

export interface Root {
  user: User
}

JSON Formatting Example

These compact and indented objects represent the same data:

Compact:
{"name":"MiniTools","enabled":true,"items":[1,2]}

Indented:
{
  "name": "MiniTools",
  "enabled": true,
  "items": [
    1,
    2
  ]
}

Export JSON as YAML

YAML output preserves keys, values and array order, but it is a different serialization. JSON-only actions such as minifying are disabled while YAML output is selected.

Only valid JSON can be exported. If the input has a syntax error, the YAML option is unavailable until the error is fixed.

  1. Enter or import valid JSON and choose an indentation size if needed.
  2. In the result panel, switch the output format from JSON to YAML.
  3. Choose 2 or 4 space indentation, then copy the YAML or download it as a .yaml file.
JSON:
{"name":"MiniTools","enabled":true,"items":[1,2]}

YAML:
name: MiniTools
enabled: true
items:
  - 1
  - 2

Export JSON as XML

Objects become child elements and arrays use repeated item elements. Keys beginning with @ become attributes, and #text supplies element text. Null values become empty elements by default.

XML names cannot contain arbitrary characters. Invalid names are sanitized by default and reported as warnings; choose strict mode to stop with an error instead. JSON-only actions such as minifying are disabled in XML mode.

  1. Switch the output format from JSON to XML.
  2. Set the root element and array item names, choose 2 or 4 space indentation, and decide whether to include the XML declaration.
  3. Copy the XML or download it as a .xml file.
JSON:
{"user":{"@id":42,"name":"Alice","tags":["admin","editor"]}}

XML:
<?xml version="1.0" encoding="UTF-8"?>
<user id="42">
  <name>Alice</name>
  <tags>
    <item>admin</item>
    <item>editor</item>
  </tags>
</user>

Common JSON Errors

JSON requires double quotes around property names and string values. Single quotes, comments, undefined, and trailing commas are not valid JSON. For example, {"count":1,} must become {"count":1}.

Syntax validation does not check your application’s required fields, types, or business rules. This tool does not perform JSON Schema validation.

Number Precision and Round-Trip Limits

Numbers are parsed as JavaScript numbers. Integers outside the safe range −9,007,199,254,740,991 to 9,007,199,254,740,991 may lose precision. Store identifiers requiring exact digits as quoted strings before processing.

Formatting is not a byte-preserving operation: number notation, escapes and whitespace may change, and duplicate object keys collapse to the last value. Keep the original when exact source text matters. The standalone JSON value null is valid and produces a null result.

Frequently Asked Questions

What is the difference between formatting and minifying JSON?

Formatting adds indentation and line breaks for readability. Minifying removes unnecessary whitespace. Both parse and serialize the input, so the round-trip limitations above apply.

Can I convert JSON to YAML here?

Yes. Select YAML in the result panel. The tool generates YAML locally from the current JSON value, supports 2 or 4 space indentation, and lets you copy or download the result.

Can I convert YAML to JSON here?

Yes. Paste YAML and use Auto-detect or select YAML as the input format. YAML mappings become JSON objects, sequences become arrays, and multi-document YAML becomes a JSON array. Binary values, complex keys and circular aliases are rejected.

Can I convert XML to JSON here?

Yes. Paste XML and use Auto-detect or select XML as the input format. Attributes become @ keys, repeated item elements become arrays, and empty elements become null by default. Mixed content is reported as lossy, and DOCTYPE declarations are rejected.

Can I convert between JSON and CSV/TSV?

Yes. CSV/TSV can be imported as JSON, and JSON arrays of records can be exported as CSV or TSV. CSV is flat, so nested objects, arrays, types and null/empty-string distinctions may be lossy. Review the CSV warnings before exporting.

Can I rename or choose CSV columns?

Yes. Open Field mapping in the CSV options to choose source fields, rename output columns, reorder them, flatten nested paths, join arrays, and apply basic type transforms.

What is JSONL?

JSONL (JSON Lines or NDJSON) stores one complete JSON value per line. It is useful for logs and streaming data. This page can import JSONL as a JSON array and export a JSON array as JSONL.

What JSONPath features are supported?

The query editor supports root $, dot and bracket child access, array indexes and slices, wildcards, recursive descent, and filters using @, comparison operators and &&/||. Results can be copied or exported as JSON or CSV.

Can I generate TypeScript interfaces or JSON Schema?

Yes. The Generate tab infers nested TypeScript interfaces or a Draft 2020-12 JSON Schema from the current JSON. You can set the root name, mark all fields optional, and allow additional properties for JSON Schema.

Can I convert JSON to XML here?

Yes. Select XML in the result panel. You can set the root element, array item name, indentation and XML declaration. JSON objects become elements, arrays use repeated item elements, @ keys become attributes, and #text becomes element text.

Does this formatter support JSON comments or trailing commas?

No. Remove comments and trailing commas first. JavaScript object literals and JSON5 are not accepted as strict JSON.

Can I validate an API response here?

Yes, paste its JSON body to check syntax and inspect its structure. A syntax pass does not establish that the response matches an API schema.

Is my JSON uploaded?

The formatting and validation code runs in your browser and does not send the JSON input to a processing server. The website also loads third-party analytics and advertising scripts.
