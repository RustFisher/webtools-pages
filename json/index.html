Online JSON/YAML/XML Formatter, Validator and Converter

Make JSON easier to read, check its syntax, remove unnecessary whitespace, import YAML or XML as JSON, or export JSON as YAML or XML. The formatter uses your browser’s parsers and serializers; processing happens locally.

How to Format and Validate JSON

  1. Paste a JSON object or array into the input area, or load the sample.
  2. Choose an indentation size and select Format. Use the tree view to inspect nested values.
  3. Select Validate to check syntax, or Compress to produce compact JSON.
  4. Copy the output after checking the result.

Import YAML as JSON

YAML mappings become JSON objects, sequences become arrays, and anchors, aliases and merge keys are resolved. Multiple YAML documents separated by --- are converted into a JSON array and reported as a warning.

Binary values, complex non-scalar keys, circular aliases and unsupported tags are rejected instead of being silently converted.

  1. Paste or import YAML and keep the input format on Auto-detect, or choose YAML explicitly.
  2. The page validates the YAML and converts it to a JSON value.
  3. Inspect the result in the JSON tree, text or table view, then copy or download it as JSON.
YAML:
user:
  name: Alice
  tags:
    - admin
    - editor
  active: true

JSON:
{
  "user": {
    "name": "Alice",
    "tags": ["admin", "editor"],
    "active": true
  }
}

Import XML as JSON

Attributes use the @ prefix, text content uses #text when attributes or child elements are present, and repeated item elements become arrays. The root element is kept by default.

XML has no native number or boolean types, so text stays as strings unless type inference is enabled. Mixed content may lose its original order, namespace prefixes are preserved by default, and DOCTYPE declarations are rejected.

  1. Paste or import XML and keep the input format on Auto-detect, or choose XML explicitly.
  2. Adjust the XML input options if needed: keep the root element, unwrap item arrays, or choose how empty elements are represented.
  3. Inspect the JSON result in the tree, text or table view, then copy or download it.
XML:
<user id="42">
  <name>Alice</name>
  <tags>
    <item>admin</item>
    <item>editor</item>
  </tags>
  <note/>
</user>

JSON:
{
  "user": {
    "@id": "42",
    "name": "Alice",
    "tags": ["admin", "editor"],
    "note": null
  }
}

JSON Formatting Example

These compact and indented objects represent the same data:

Compact:
{"name":"MiniTools","enabled":true,"items":[1,2]}

Indented:
{
  "name": "MiniTools",
  "enabled": true,
  "items": [
    1,
    2
  ]
}

Export JSON as YAML

YAML output preserves keys, values and array order, but it is a different serialization. JSON-only actions such as minifying are disabled while YAML output is selected.

Only valid JSON can be exported. If the input has a syntax error, the YAML option is unavailable until the error is fixed.

  1. Enter or import valid JSON and choose an indentation size if needed.
  2. In the result panel, switch the output format from JSON to YAML.
  3. Choose 2 or 4 space indentation, then copy the YAML or download it as a .yaml file.
JSON:
{"name":"MiniTools","enabled":true,"items":[1,2]}

YAML:
name: MiniTools
enabled: true
items:
  - 1
  - 2

Export JSON as XML

Objects become child elements and arrays use repeated item elements. Keys beginning with @ become attributes, and #text supplies element text. Null values become empty elements by default.

XML names cannot contain arbitrary characters. Invalid names are sanitized by default and reported as warnings; choose strict mode to stop with an error instead. JSON-only actions such as minifying are disabled in XML mode.

  1. Switch the output format from JSON to XML.
  2. Set the root element and array item names, choose 2 or 4 space indentation, and decide whether to include the XML declaration.
  3. Copy the XML or download it as a .xml file.
JSON:
{"user":{"@id":42,"name":"Alice","tags":["admin","editor"]}}

XML:
<?xml version="1.0" encoding="UTF-8"?>
<user id="42">
  <name>Alice</name>
  <tags>
    <item>admin</item>
    <item>editor</item>
  </tags>
</user>

Common JSON Errors

JSON requires double quotes around property names and string values. Single quotes, comments, undefined, and trailing commas are not valid JSON. For example, {"count":1,} must become {"count":1}.

Syntax validation does not check your application’s required fields, types, or business rules. This tool does not perform JSON Schema validation.

Number Precision and Round-Trip Limits

Numbers are parsed as JavaScript numbers. Integers outside the safe range −9,007,199,254,740,991 to 9,007,199,254,740,991 may lose precision. Store identifiers requiring exact digits as quoted strings before processing.

Formatting is not a byte-preserving operation: number notation, escapes and whitespace may change, and duplicate object keys collapse to the last value. Keep the original when exact source text matters. The standalone JSON value null is valid, but this interface currently does not generate a new output for it.

Frequently Asked Questions

What is the difference between formatting and minifying JSON?

Formatting adds indentation and line breaks for readability. Minifying removes unnecessary whitespace. Both parse and serialize the input, so the round-trip limitations above apply.

Can I convert JSON to YAML here?

Yes. Select YAML in the result panel. The tool generates YAML locally from the current JSON value, supports 2 or 4 space indentation, and lets you copy or download the result.

Can I convert YAML to JSON here?

Yes. Paste YAML and use Auto-detect or select YAML as the input format. YAML mappings become JSON objects, sequences become arrays, and multi-document YAML becomes a JSON array. Binary values, complex keys and circular aliases are rejected.

Can I convert XML to JSON here?

Yes. Paste XML and use Auto-detect or select XML as the input format. Attributes become @ keys, repeated item elements become arrays, and empty elements become null by default. Mixed content is reported as lossy, and DOCTYPE declarations are rejected.

Can I convert JSON to XML here?

Yes. Select XML in the result panel. You can set the root element, array item name, indentation and XML declaration. JSON objects become elements, arrays use repeated item elements, @ keys become attributes, and #text becomes element text.

Does this formatter support JSON comments or trailing commas?

No. Remove comments and trailing commas first. JavaScript object literals and JSON5 are not accepted as strict JSON.

Can I validate an API response here?

Yes, paste its JSON body to check syntax and inspect its structure. A syntax pass does not establish that the response matches an API schema.

Is my JSON uploaded?

The formatting and validation code runs in your browser and does not send the JSON input to a processing server. The website also loads third-party analytics and advertising scripts.
